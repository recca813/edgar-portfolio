Local AI Voice Assistant

Push-to-talk, answered by a model running on your own hardware, over your own notes — no internet required.

llama.cpp Gemma faster-whisper Kokoro TTS Next.js Node.js Docker

01 / Problem

Cloud voice assistants mean sending every question, and often personal notes as context, to a third-party API. That's a hard tradeoff for something meant to answer questions from a personal knowledge base — and it stops working the moment the connection does.

02 / Approach

Built the whole loop — listening, thinking, and speaking — to run locally by default, with cloud APIs wired in only as a fallback if a local service is down, not as the primary path. The goal was to see how far "no cloud dependency" could actually go for a real, daily-use assistant.

03 / What Was Built

A push-to-talk voice assistant where speech is captured and transcribed locally with faster-whisper, then answered by a Gemma 4 12B model served locally via llama.cpp, using a personal Markdown vault as its knowledge base for retrieval-augmented answers. Replies are spoken aloud through Kokoro, a local neural TTS engine, with no round trip to a cloud model required for a normal question. Cloud APIs (a hosted LLM, a hosted TTS service) are wired in as fallback only, triggered if a local service's health check fails, so the assistant keeps answering even if a local component goes down — just not fully offline in that moment.

04 / Outcome

A working, daily-use voice assistant with no hard dependency on an internet connection or a third party seeing personal notes to answer a question.
